# System Specification: ระบบฝากขาย OTC (ฉบับลงลึกรายละเอียด)


---

## 1. โครงสร้างฐานข้อมูล (Database Schema)
แบ่งออกเป็น 5 ตารางหลัก ดังนี้

### 1.1 ตาราง `tb_users` (ข้อมูลผู้ใช้งาน)
เก็บข้อมูลบัญชีผู้ใช้สำหรับล็อกอินและการกำหนดสิทธิ์
* **`UserID`**: รหัสผู้ใช้งาน (Primary Key) เช่น USR001
* **`Username`**: ชื่อผู้ใช้สำหรับล็อกอิน
* **`Password`**: รหัสผ่าน
* **`FullName`**: ชื่อ-นามสกุลจริงของผู้ใช้งาน
* **`Role`**: บทบาทการเข้าถึงระบบ (`System_Admin`, `Admin`, `Sale`)
* **`Status`**: สถานะบัญชี (`Active` = ใช้งานได้, `Inactive` = ระงับการใช้งาน)

### 1.2 ตาราง `tb_products` (ข้อมูลสินค้าหลัก)
เก็บข้อมูล Master Data ของสินค้า
* **`ProductID`**: รหัสสินค้าในระบบ (Primary Key) เช่น PRD001
* **`SKU`**: รหัสรหัสสินค้า (Stock Keeping Unit)
* **`ProductName`**: ชื่อสินค้า
* **`Price`**: ราคาขายต่อหน่วย
* **`StartDate`**: วันที่เริ่มเปิดขายสินค้านี้
* **`EndDate`**: วันที่สิ้นสุดการขาย (ถ้ามี)
* **`Status`**: สถานะของสินค้า (`Active`, `Inactive`)

### 1.3 ตาราง `tb_stores` (ข้อมูลร้านยา/สถานที่ฝากขาย)
เก็บข้อมูล Master Data ของร้านลูกค้าที่นำสินค้าไปวาง
* **`StoreID`**: รหัสร้านค้า (Primary Key) เช่น STR001
* **`StoreName`**: ชื่อร้านยา หรือ คลินิก
* **`Location`**: ที่อยู่หรือพิกัดของร้าน
* **`Assigned_UserID`**: รหัสพนักงานขาย (Sale) ที่รับผิดชอบดูแลร้านนี้ (เชื่อมโยงกับ `tb_users.UserID`)

### 1.4 ตาราง `tb_inventory` (ตารางคลังสินค้า)
หัวใจหลักของการควบคุมสต็อกแบบ 2 ระดับ จะเก็บยอดคงเหลือแบบแยกตามสถานที่
* **`InvID`**: รหัสรายการคลังสินค้า
* **`ProductID`**: รหัสสินค้าที่อ้างอิง (`tb_products.ProductID`)
* **`LocationType`**: ประเภทของคลังที่เก็บสินค้า มี 2 แบบคือ:
  * `Sale` = สินค้าอยู่กับตัวพนักงานขาย (สต็อกเซลล์)
  * `Pharmacy` = สินค้าฝากอยู่ที่ร้านยา (สต็อกร้านยา)
* **`LocationID`**: รหัสอ้างอิงสถานที่ 
  * ถ้า `LocationType` เป็น Sale ช่องนี้จะเก็บ `UserID`
  * ถ้า `LocationType` เป็น Pharmacy ช่องนี้จะเก็บ `StoreID`
* **`Quantity`**: จำนวนสินค้าคงเหลือปัจจุบันในสถานที่นั้นๆ

### 1.5 ตาราง `tb_transactions` (ประวัติการทำรายการ/ความเคลื่อนไหว)
เก็บ Log ทุกรายการที่เซลล์กดทำรายการเข้ามา เพื่อรอแอดมินอนุมัติ
* **`DocNo`**: เลขที่เอกสาร/เลขที่อ้างอิงการทำรายการ (Primary Key)
* **`DocType`**: ประเภทของการทำรายการ ได้แก่:
  * `Request` = ขอเบิกของเข้าสต็อกเซลล์
  * `Consign` = นำของไปฝากขายที่ร้านยา
  * `Sale` = แจ้งขายสินค้าออกจริง
  * `Return` = แจ้งส่งคืนสินค้า
* **`ReturnSubtype`**: ประเภทย่อยของการคืน (จะมีค่าเฉพาะเมื่อ `DocType` = Return)
  * `Pharmacy_to_Sale` = รับคืนจากหน้าร้านเข้าสต็อกเซลล์
  * `Sale_to_Company` = คืนจากเซลล์กลับบริษัท
* **`ProductID`**: รหัสสินค้าที่ทำรายการ
* **`Quantity`**: จำนวนสินค้าที่ทำรายการ
* **`LocationID`**: รหัสร้านยา (StoreID) ที่ทำรายการฝาก/ขาย (กรณีทำรายการที่เกี่ยวข้องกับร้านยา)
* **`CreatedBy`**: รหัสเซลล์ที่กดทำรายการ (`UserID`)
* **`Timestamp`**: วันที่และเวลาที่เซลล์กดทำรายการ
* **`Status`**: สถานะการอนุมัติ (`Pending` รออนุมัติ, `Approved` อนุมัติแล้ว, `Rejected` ปฏิเสธ)
* **`EvidenceImg`**: URL หรือรหัสไฟล์รูปภาพหลักฐานสลิป (บันทึกใน Google Drive)
* **`ApprovedBy`**: รหัสแอดมินที่กดอนุมัติรายการ
* **`ApprovedTimestamp`**: วันที่และเวลาที่แอดมินกดอนุมัติ
* **`Remark`**: หมายเหตุ หรือ เหตุผลจากแอดมิน (เช่น กรณีถูก Reject)

---

## 2. การทำงานร่วมกันระหว่าง เมนู (UI) และ ฐานข้อมูล (Database)

### 2.1 หน้า Dashboard (Web App Admin)
* **การทำงาน:** ระบบจะนับจำนวนรายการ (Count) จากตาราง `tb_transactions` ที่ `Status` = 'Pending' เพื่อโชว์จำนวนงานที่แอดมินต้องทำ
* **การทำงาน:** ระบบบวกยอดรวมจาก `tb_inventory` เพื่อโชว์ยอดสต็อกรวม
* **การทำงาน:** นับจำนวน User จาก `tb_users` ที่มี `Role` = 'Sale'

### 2.2 การอนุมัติ - Approvals (Web App Admin)
* **การทำงาน (ตอนดึงข้อมูล):** ระบบดึงข้อมูลจาก `tb_transactions` เฉพาะแถวที่ `Status` = 'Pending' มาแสดง โดยทำการ Join กับ `tb_users` (ดึงชื่อเซลล์), `tb_products` (ดึงชื่อสินค้า) และ `tb_stores` (ดึงชื่อร้าน)
* **การทำงาน (ตอนกดอนุมัติ Approve):** 
  1. ระบบจะอัปเดตสถานะใน `tb_transactions` เปลี่ยน `Status` เป็น 'Approved' บันทึก `ApprovedBy` และ `ApprovedTimestamp`
  2. **Inventory State Machine** จะทำงานทันที เพื่อบวก/ลบยอดใน `tb_inventory` ตัวอย่างเช่น:
     * หากเป็นรายการเบิก (`Request`): ไปค้นหา/เพิ่มแถวใน `tb_inventory` ที่ `LocationType`='Sale' และบวก `Quantity` เพิ่ม
     * หากเป็นรายการฝากขาย (`Consign`): ไปลบยอด `Quantity` ออกจากสต็อก Sale และไปบวกเพิ่มที่สต็อก Pharmacy แทน
* **การทำงาน (ตอนกดปฏิเสธ Reject):** อัปเดต `Status` เป็น 'Rejected' และใส่เหตุผลใน `Remark` (สต็อกใน `tb_inventory` จะไม่ถูกแก้ไขใดๆ)

### 2.3 ตรวจสอบคลังสินค้า (Admin & Mobile App)
* **คลังเซลล์:** ดึงข้อมูลจาก `tb_inventory` โดยฟิลเตอร์เฉพาะ `LocationType` = 'Sale'
  * *สำหรับ Admin:* เห็นเซลล์ทุกคน
  * *สำหรับ Mobile Sale:* ฟิลเตอร์เพิ่มให้ `LocationID` ตรงกับ UserID ของตนเองเท่านั้น
* **คลังร้านยา:** ดึงข้อมูลจาก `tb_inventory` โดยฟิลเตอร์เฉพาะ `LocationType` = 'Pharmacy'
  * *สำหรับ Mobile Sale:* จะ Join กับตาราง `tb_stores` เพื่อดูเฉพาะร้านที่ `Assigned_UserID` ตรงกับตนเอง

### 2.4 ตั้งค่า Master Data (Web App Admin)
* **การใช้งาน:** เมนูนี้คือหน้าจอสำหรับทำ CRUD (Create, Read, Update, Delete) ให้กับตาราง `tb_products`, `tb_stores`, และ `tb_users` โดยตรง ข้อมูลที่แก้ตรงนี้จะสะท้อนไปที่ Dropdown ในแอปมือถือของเซลล์ทันที

### 2.5 ทำรายการ Actions (Mobile App Sale)
หน้าจอนี้รับข้อมูลจากเซลล์และบันทึกลง `tb_transactions` เป็นหลัก
* **ฟิลด์ที่ดึงมาแสดง (Inputs):** 
  * รายชื่อสินค้า: ดึงมาจาก `tb_products` ที่สถานะ Active
  * รายชื่อร้านยา: ดึงมาจาก `tb_stores` เฉพาะร้านที่ Sale คนนั้นดูแล
* **การทำงานเมื่อกด Submit:** 
  1. ระบบรับข้อมูล ประเภทรายการ, รหัสสินค้า, จำนวน, ร้านยา
  2. หากเป็น "ขายจริงออกหน้าร้าน" (Sale) ระบบจะบังคับให้เซลล์กดถ่ายรูป/เลือกรูปสลิป 
  3. รูปภาพจะถูกส่งไปแปลงไฟล์และบันทึกลง Google Drive ของแอดมิน คืนค่ากลับมาเป็น Image URL
  4. ระบบจะเพิ่มแถวใหม่ (Insert Row) ในตาราง `tb_transactions` โดยใส่ค่า `DocType`, `ProductID`, `Quantity`, ใส่ URL รูปลงใน `EvidenceImg` และกำหนด `Status` เริ่มต้นเป็น 'Pending' เสมอ
